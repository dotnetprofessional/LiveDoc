# xUnit SDK

<p className="intro">
Living documentation for .NET projects. Write tests that double as documentation —
from unit-level specifications to full end-to-end API journeys.
</p>

## Three Ways to Document Your Code

<div className="features-grid">

<div className="feature-card">
<div className="feature-icon">🧪</div>
<h3>BDD Features</h3>
<p>Gherkin-style Given / When / Then scenarios that read like plain English. Perfect for acceptance tests and business-facing documentation.</p>
<p><a href="./learn/your-first-feature"><strong>Write your first feature →</strong></a></p>
</div>

<div className="feature-card">
<div className="feature-icon">📐</div>
<h3>Specifications</h3>
<p>Lightweight, developer-focused rules for unit and component tests. Less ceremony than BDD — ideal for testing algorithms and edge cases.</p>
<p><a href="./learn/your-first-spec"><strong>Write your first spec →</strong></a></p>
</div>

<div className="feature-card">
<div className="feature-icon">🗺️</div>
<h3>Journey Testing</h3>
<p>End-to-end API testing with annotated <code>.http</code> files. Your API journeys work as both manual exploration tools <em>and</em> automated regression tests with response contract validation.</p>
<p><a href="./guides/journey-testing"><strong>Explore journey testing →</strong></a></p>
</div>

</div>
